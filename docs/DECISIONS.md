| D1 | LLM models | Generator and tutor: claude-sonnet-4-6. Critic: gpt-4o. Tutor fallback: claude-haiku-4-5 | Cross vendor critic gives independent verification for FR3. Sonnet has strong Hebrew and structured JSON output | 2026-07-06 |
| D2 | Embeddings | text-embedding-3-large | Multilingual, strong Hebrew performance, OpenAI key already required for the critic | 2026-07-06 |
| D3 | Vector store | Firestore native vector search (find_nearest) | One less service, sufficient at capstone scale, keeps the memory bank inside the existing data layer | 2026-07-06 |
| D4 | Standards corpus | Israeli MOE math curriculum, curated into a static JSON shipped in repo | No public API exists. A curated snapshot is reproducible and citable | 2026-07-06 |
| D5 | Content and UI language | Hebrew (RTL) | Target users are Israeli teachers and students | 2026-07-06 |
| D6 | BERTScore scorer | xlm-roberta-large | Default roberta-large is English only and invalid for Hebrew. Scorer model recorded in every results file | 2026-07-06 |
| D7 | Comment style | Clean and concise. No em dashes, emojis, arrows, or semicolons in comments. Python type hint arrows are syntax and exempt | Team convention | 2026-07-06 |
| D8 | Subject scope | All subjects. The platform generates enrichment programs for any subject with a curated standards corpus. Subject is a first class parameter everywhere | Official project scope covers all subjects, not only math | 2026-07-08 |
| D9 | Evaluation strategy for all subjects | Stratified subject sampling. NLP metrics and expert rubric run on three representative subjects: one quantitative (math), one mixed (science), one open ended (history or literature). Gold references and subject competent raters per sampled subject. NLP similarity metrics are paired with critic correctness accuracy per subject type, since ROUGE, BLEU and BERTScore measure similarity to references, not factual correctness. Behavioral metrics (NGS, ATT, TCV, HSR) and CAR are subject agnostic and run on whatever subjects the pilot uses | Evaluating every possible subject is infeasible. Sampling one subject per subject type gives generalization evidence. Similarity metrics alone cannot detect factual errors in open ended content | 2026-07-08 |
| D10 | Use case model revision | Fig 1 now shows actor goal use cases only: 4 student (View History, Browse and Select, Solve Problems, Interact with Teachable Agent) and 5 teacher (Create Program, Publish to Distribution List, View Performance Evaluation, Monitor Student Analytics, Review Content with Modify Content extend). Internal automation (generation, self correction, scoring, memory learning, affective detection, scaffolding) is no longer modeled as use cases and lives in FR2, FR3, FR4, FR6, FR10, FR12 unchanged | Standard UML practice: use cases model actor goals, not internal system behavior. No feature was descoped | 2026-07-08 |
| D11 | Answer protection storage split | Each exercise persists as a student safe exercises doc plus a teacher only exerciseSolutions doc with the same id. Student read gating uses assignedStudentKeys arrays denormalized at publish time | Firestore rules cannot hide fields of a readable doc, and list rules must be provable from query filters, so a get based rule would reject student queries. Deliberate improvement over the book flat exercise doc, see docs/API_CONTRACT.md | 2026-08-15 |
| D12 | Science subject type for the critic (Q12) | open_ended, claim verification | D9 calls science a mixed subject but the critic strategy map is two valued. The curated elementary science standards are conceptual, so claim verification fits. A calculation heavy science unit would get claim checking rather than an independent solve, revisit if the pilot needs one | 2026-11-18 |
| D13 | NFR2 re-scope (Q10) | Split into NFR2a, interactive tutor turn p95 <= 15s, and NFR2b, curriculum generation p95 <= 900s | The Phase A NFR2 put 15s on generate plus score plus self correct. A package is roughly 4000 to 5500 output tokens across 7 sequential model calls, so 15s is unreachable without removing the critic loop or the lesson content. Measured DEV runs: about 190s for a single pass, 253s to 673s end to end (evaluation/results/dev_runs/summary.json). The 15s figure is kept where responsiveness is actually felt, the student facing tutor turn. Both figures are Phase B targets, not results (R1). PENDING ADVISOR APPROVAL, the Phase A book specifies the original single NFR2 | 2026-11-18 |
| D14 | Critic mismatch confirmation (Q11) | A normalization guard mismatch is re-solved blind a second time and kept only when that solve also disagrees with the stated answer | On the difficulty 5 dev brief 2 of 3 final wrong_answer flags came from errors in the critic's own blind solve, so a correct unit reached the teacher unapproved. Costs one extra call and only when answers disagree. Dropping a flag requires positive agreement, an undecidable comparison keeps it, so no real error is traded away for fewer false positives | 2026-11-18 |
